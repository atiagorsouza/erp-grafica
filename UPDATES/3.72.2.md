# Boletim 3.72.2 — Reconciliação: Visão Geral confiável + blindagens de deploy

Pacote produzido pela sessão de desenvolvimento que também criou o
protocolo do agente (3.70.0/3.70.1). O conteúdo ficou retido no
sandbox quando a sessão fechou após o merge do PR #6; este release
reconcilia em cima do main atual (3.72.1). **Sem migração de banco.**

## O que vem

### A) Correções de deploy (comprovadas no incidente de hoje)

1. **`update.sh` acha o pg_dump certo sozinho** (`escolher_pgdump`):
   consulta o major do servidor (`SHOW server_version_num`), varre
   `command -v pg_dump` + `/usr/lib/postgresql/*/bin` +
   **`/www/server/pgsql*/bin` (aPanel)** e usa o binário compatível.
   Fim do `export PATH` manual — o PATH não sobrevive entre shells do
   agente, como hoje provou.
2. **`update.sh` carimba a versão no fim** (`carimbar_versao` →
   `check-version --fix`): quem atualizava ficava com o carimbo da
   versão anterior e o smoke reprovava na checagem 11.8. Era a
   pendência #1 do incidente 25/08.
3. **Bug do validador do backup JSON** (derrubou o update de hoje):
   `require('./<caminho-absoluto>')` virava `.//www/...` → "Cannot
   find module" → abort com o dump JSON gravado. Validação agora
   recebe o caminho por `argv`.
4. **Documentação da topologia real**: banco = PostgreSQL 18.0 do
   aPanel (`/www/server/pgsql`); o cluster 17 local NÃO é do ERP.
   MANUAL §1.1 corrigido (explicava o mismatch ao contrário) + receita
   Docker.

### B) Visão Geral (dashboard) — módulo 1 da varredura

5. KPI "14 dias" coerente (contagem da janela, não do histórico);
   ticket médio rotulado "· 14d"
6. Data dos orçamentos recentes formatada NO SERVIDOR (fuso
   America/Sao_Paulo) — era no navegador; criado 21h aparecia como
   "dia seguinte"
7. Faixa operacional: chips Em produção / Estoque crítico (vermelho
   quando há) / Clientes ativos / No catálogo
8. Estoque crítico "+N" quando há mais além dos 6 exibidos
9. Sparkline fluida (viewBox) e tooltip do gráfico abre no toque

## O que você (agente) deve fazer

Deploy padrão do §4 do `AGENTE-SERVIDOR.md` **após o merge**:
`git pull origin main` → `bash scripts/update.sh` → `pm2 restart` →
`/api/version` → `e2e:smoke` → `agente-verificar.mjs`.
A partir desta versão o update carimba sozinho e acha o pg_dump sozinho.

## Lições do deploy de hoje (27/08) — registradas no manual

- `export PATH` vale só no shell atual: update precisa rodar NO
  MESMO SHELL do export (agora irrelevante: item 1 acima)
- Processo `next-server` ANTIGO pode ficar segurando a porta 3000
  fora do PM2 (PM2 "zerado" não o mata). Sintoma: API mostra versão
  que não existe mais no código. Matança pelo nome E porta
  (`pkill -9 -f next-server` + `fuser -k 3000/tcp`)
- `pm2 save` após toda mudança na lista do PM2
- Update cortado por timeout NÃO terminou: conferir BUILD_ID antes de
  prosseguir (rebuild é idempotente — rode de novo se preciso)
