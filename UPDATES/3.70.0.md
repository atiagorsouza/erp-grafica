# Boletim 3.70.0 — Blindagem e Árvore v2

## O que mudou

1. **Tabelas do WhatsApp entraram no schema do ERP** (`whatsapp_conversas`,
   `whatsapp_mensagens`, `whatsapp_auth` em `src/db/schema.ts`). Era a
   pendência "Blindagem v3.68.9" do incidente de 25/08: antes, qualquer
   `drizzle-kit push` enxergava essas tabelas como sobra e propunha DROP
   — era o risco de perder o histórico de conversas. Agora o Drizzle
   GERENCIA as tabelas, com definições idênticas às que o serviço cria.
   - **Efeito no update:** se o serviço do bot já criou as tabelas, o
     push não faz nada (ou só adiciona colunas ausentes, aditivo). Se o
     bot nunca rodou, o push cria as tabelas vazias — o serviço continua
     funcionando (`CREATE TABLE IF NOT EXISTS` é idempotente).
   - **Atenção:** o push do `update.sh` pode listar `whatsapp_*` como
     "novas tabelas". Isso é esperado e seguro. Se ele propor DROP de
     qualquer tabela, **PARE e reporte** — é bug no boletim, não caminho.
2. **Bug do contador de orçamento**: primeira cotação após seed/importação
   devolvia **500** (número duplicado). Corrigido no seed + `createQuote`
   agora regenera o número em conflito (até 3 tentativas).
3. **`check-version.mjs` sem `psql`**: passou a usar o driver `pg`. Banco
   inalcançável agora é **erro barulhento** (antes: silêncio e "consistente"
   falso). Na prática: o carimbo `settings.app_version` vai ser gravado
   pelo próprio update (passo 7 do `check-version`).
4. **Seed com a árvore de categorias v2** (10 mestres + subcategorias,
   `docs/ARVORE-CATEGORIAS.md`) — afeta apenas instalações NOVAS;
   produção não é re-semeada, sua árvore atual continua como está.
5. **`install.sh`** do zero agora aplica logos e carimba versão.

## O que você (agente) deve fazer

Fluxo padrão do §4 do `AGENTE-SERVIDOR.md`:

```bash
git pull origin main
bash scripts/update.sh
pm2 restart <nome>            # ou bash scripts/start.sh
set -a; source .env; set +a && npm run e2e:smoke
node scripts/check-version.mjs
```

## Como validar

- `/api/version` → `"version":"3.70.0"` e `"upToDate":true`
- `e2e:smoke` → "🎉 concluído com sucesso" (308 checks)
- `/whatsapp` abre normal e as conversas continuam listando
  (a migração NÃO toca nos dados das tabelas do WhatsApp)

## Rollback

Padrão do §7 do `AGENTE-SERVIDOR.md`. Esta versão não altera dados
existentes — apenas cria tabelas se faltarem. Voltar o código + rebuild
suficiente; restaurar banco só se algo estranho aparecer nas conversas.
